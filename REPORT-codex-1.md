## Round 4 - memory hot paths and temporary ownership

### Changes made

- Replaced heap-header atomic RC fields with plain `uint32_t` counts. Before the first worker starts, retain/release use direct reads and writes, and collector registry operations skip the mutex. `hp_runtime_thread_starting()` switches the process to compiler atomic RC builtins and the collector mutex before creating a worker. Threaded positive tests passed.
- Applied `plans/claude-temp-fix.patch` and added `tests/positive/memory_temp_operands.hphp`. Binary operations now drop fresh owned operands after use. Managed builtin results are treated as owned by default, with known result-aliasing helpers excluded. Generic builtin arguments that are fresh temporaries are held through the call and then released. Fresh match subjects and template interpolation operands are released after evaluation; conditions share the owned temporary path. Echo/print already retained borrowed values and released their call-local owner.
- Generated string literal sites use a static atomic handle cache: after first evaluation a site performs a cache load, without the runtime literal-pool lock or list scan. Cleanup registration now appends to a reusable thread-local vector; scope marks are vector indices, replacing one allocated node per owner.
- Updated `docs/lang.html`, `docs/guide/memory-model.md`, and `CHANGELOG.md`.
