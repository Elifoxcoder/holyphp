# Codex tasks 1.1–1.3 report

## Changed

- `src/hphpc/runtime/hphp_rt.h`, `src/hphpc/runtime/hphp_rt.c`: implemented saturating RC hooks and release paths for strings, arrays, closures, and generated objects. Objects use a common header and generated class drop callback. Array entries release replaced values and keys; COW clones retain their contents. Raw array mutators require writable storage; COW occurs in helpers that can install/return the detached owner. Added owner-aware writes, nested-path COW, and owner-aware unset. Closures drop captured values and by-reference boxes. Cleanup stack supports scope and exception unwinding.
- `src/hphpc/codegen.c`: generated classes include object headers/drop callbacks. Generated code retains borrowed heap values and releases assigned/parameter/local/return owners across normal scope exit, early returns, loop exits, and exception cleanup. Array writes and unset use owner-aware COW helpers; nested writes detach each path segment.
- `src/hphpc/runtime_embed.h`: regenerated by `scripts/build.sh`.
- `packages/lib/html/dom.hphp`: threaded the returned array through recursive `allByClass` calls so writes preserve COW value semantics.
- `tests/positive/memory_rc.hphp`, `tests/positive/memory_rc_rss.ps1`, `tests/positive/memory_cow_unset.hphp`: allocation churn and RSS flattening for strings, arrays, objects, and capturing closures; regression for unset COW.

## Round 2 — safety plan continuation

### Changes

- Added runtime graph tracing and trial-deletion cycle collection for generated
  objects and closures, including captured objects. Weak properties are parsed,
  type-checked, emitted and invalidated when their targets die; reading a dead
  weak target yields `null`. The collector traces only the candidate's reachable
  subgraph and clears all dead-node edges before freeing payloads.
- Added `declare(enforce_memory_safety=1);` per file. It rejects unsafe blocks
  and calls to builtins marked unsafe in `builtins.c`, with positive and
  negative fixtures.
- Added runtime bounds and key-type checks for list and string indexing.
  Invalid reads raise catchable errors; missing map keys retain their existing
  `null` behavior. The compiler emits each check; proof-based elision is not
  implemented.
- Added a conservative partial thread capture check. Direct closure literals
  passed to `thr_spawn`/`thr_parallel_map` reject by-reference and known
  non-Sync captures. Indirect callbacks are rejected, and user classes cannot
  claim Sync through a class-name convention. A real thread/channel positive
  test exposed that generated `hpbi_*` call names did not select the thread
  runtime; runtime selection is fixed. Spawned closures are retained until
  creator-thread join to avoid dropping their captures while a worker runs.
  This does **not** complete task 3.4: channel ownership transfer is unchecked,
  raw heap handles and reference counts are shared across threads, and the
  bundled `Thread`/`Pool` wrappers fail the current callback restrictions.
- Reduced the IDE workbench fixture's filler files from 60 to 40 while keeping
  its required tree size above the visible explorer rows.
- Updated `docs/lang.html`, `docs/guide/memory-model.md`, and `CHANGELOG.md`.

## Round 4 � memory hot paths and temporary ownership

### Changes made

- Replaced heap-header atomic RC fields with plain `uint32_t` counts. Before the first worker starts, retain/release use direct reads and writes, and collector registry operations skip the mutex. `hp_runtime_thread_starting()` switches the process to compiler atomic RC builtins and the collector mutex before creating a worker. Threaded positive tests passed.
- Applied `plans/claude-temp-fix.patch` and added `tests/positive/memory_temp_operands.hphp`. Binary operations now drop fresh owned operands after use. Managed builtin results are treated as owned by default, with known result-aliasing helpers excluded. Generic builtin arguments that are fresh temporaries are held through the call and then released. Fresh match subjects and template interpolation operands are released after evaluation; conditions share the owned temporary path. Echo/print already retained borrowed values and released their call-local owner.
- Generated string literal sites use a static atomic handle cache: after first evaluation a site performs a cache load, without the runtime literal-pool lock or list scan. Cleanup registration now appends to a reusable thread-local vector; scope marks are vector indices, replacing one allocated node per owner.
- Updated `docs/lang.html`, `docs/guide/memory-model.md`, and `CHANGELOG.md`.

### Measurements
